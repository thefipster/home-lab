# Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add [gethomepage/homepage](https://github.com/gethomepage/homepage) to the
infra VM as `infra/homepage/`, routed at `home.thefipster.de` and gated by Authentik
forward-auth, with every registry, guide and cross-reference in the repo updated to
match.

**Architecture:** An ordinary infra-VM compose stack — `compose.yaml` plus a
git-tracked `config/` directory bind-mounted **read-only**, symlinked into
`/opt/stacks` by a thin init script, driven from Dockge. No `.env`, no `/opt`
data directory, no `backup.sh`. Every widget is token-free: container state from
the Docker socket, service health from Uptime Kuma's existing `homelab` status
page.

**Tech Stack:** Docker Compose, Traefik v3 labels, Authentik forward-auth,
`ghcr.io/gethomepage/homepage:v1`, Markdown.

**Spec:** [docs/superpowers/specs/2026-08-08-homepage-design.md](../specs/2026-08-08-homepage-design.md)

## Global Constraints

- **No host IP addresses anywhere.** Machines are addressed by name. A literal
  address is a flag, not a detail.
- **Image pins are major-only.** `ghcr.io/gethomepage/homepage:v1` — verified
  published against ghcr (`v1`, `v1.4`, `v1.4.5` all exist; `v1` is the pin).
- **LF line endings.** `.gitattributes` forces LF repo-wide; `*.sh` must stay LF
  or the shebang breaks on the VM.
- **`scripts/init-homepage.sh` must be committed mode `100755`.** Files created
  on Windows default to `100644`; fix with `git update-index --chmod=+x`.
- **No per-router TLS labels.** The `websecure` entrypoint's wildcard covers every
  router. Add no `certresolver`, no `tls.domains`.
- **Guides describe a from-scratch bring-up of the current checkout.** No migration
  paths, no upgrade notes, no `git pull` outside an initial clone.
- **Guide structure is fixed**, in this order: headline; `**Runs on:**` line;
  one-line prerequisite linking the previous guide; short explanation of the
  stack; numbered steps with verification, each command in its own fenced block;
  jump-off to the next guide; troubleshooting; layout on the server; detailed
  explanation / design notes; jump-off repeated.
- **Registries get their row before the service is built**, and they record
  deliberate absences beside their entries.
- **There is no test suite.** Verification in this repo is (a) `docker compose
  config -q`, (b) `python -c "import yaml; yaml.safe_load(...)"`, (c) `bash -n`,
  and (d) reading. The Docker daemon is **not** running on the authoring machine,
  so no container can be smoke-tested locally — `docker compose config` is
  client-side and works regardless.

## Two facts discovered while planning that the spec does not have

Both are load-bearing and both are fixed by Task 1.

1. **All nine of Homepage's skeleton config files must exist, or the container
   exits.** Upstream's `checkAndCopyConfig` copies a skeleton file into
   `/app/config` when it is missing and calls `process.exit(1)` when that copy
   fails. On a read-only mount every copy fails, so a missing file is a boot
   loop, not a warning. Upstream ships nine: `settings.yaml`, `services.yaml`,
   `widgets.yaml`, `bookmarks.yaml`, `docker.yaml`, `kubernetes.yaml`,
   `proxmox.yaml`, `custom.css`, `custom.js`. All nine ship in this repo; the
   last four are stubs.
2. **The Uptime Kuma widget is a *service* widget, not an info widget.** It
   attaches to the Kuma entry inside `services.yaml`. The spec's file table puts
   it in `widgets.yaml`, which is wrong. `widgets.yaml` ships as a comment-only
   file.

The spec's "Files touched" list also names `infra/uptime-kuma/compose.yaml` for
the "last stack" comment. That phrase is not in the compose — it is in
`CLAUDE.md:408`. The compose needs no edit; `scripts/init-uptime-kuma.sh` does,
because it claims Kuma is "the only stack with no `.env` at all".

- [ ] **Step 1: Write `infra/homepage/compose.yaml`**

```yaml
# Homepage — the lab's start page.
#
# Runs on the INFRA VM. One page listing every service in the lab, with live
# container state for this VM's stacks (read from the Docker API) and plain
# links for everything on the other two machines.
#
# WHY HERE AND NOT THE APPS VM: the socket below is the deciding argument. The
# daemon with the lab's stacks on it is this one; the apps VM's belongs to
# Coolify, whose container names are generated and which cannot see this
# machine at all. Homepage also ships NO authentication of its own, and the
# forward-auth middleware that fixes that exists only on this VM's Traefik.
# Full reasoning: docs/superpowers/specs/2026-08-08-homepage-design.md.
#
# Deploy (on the infra VM): scripts/init-homepage.sh, then bring it up —
# see docs/homepage-setup.md.
#   UI: https://home.thefipster.de   (via the Traefik stack — see infra/traefik)
#   Build order: Traefik and Authentik must be up FIRST — the router below is
#   gated by authentik@docker, so without them it won't load at all.
#   Break-glass: comment the middlewares label and recreate.
#
# NO .env and no .env.example — the second stack in the lab with none, after
# Uptime Kuma. Every widget is token-free (container state from the socket,
# service health from Kuma's status page), so there is no secret to seed. The
# two environment values below are neither secret nor machine-specific.
#
# NO /opt/homepage either, and this is the FIRST stack in the repo with no
# persistent data directory at all: everything Homepage owns is the git-tracked
# YAML in ./config. That is also why it has no backup.sh — see
# docs/roadmap/backup.md.

name: homepage

services:
  homepage:
    # Major-only pin, per repo policy. Verified against the registry: a bare
    # `v1` tag IS published (unlike alloy/tempo, which need a full patch pin).
    image: ghcr.io/gethomepage/homepage:v1
    restart: unless-stopped
    environment:
      # MANDATORY since v1.0 — Homepage rejects requests whose Host header is
      # not listed here, so an empty value is a 400 on every page load. No port:
      # Traefik forwards the bare name on the default HTTPS port.
      HOMEPAGE_ALLOWED_HOSTS: home.thefipster.de
      # Load-bearing, not tidiness. Homepage's default is to write a logfile
      # into /app/config/logs, which the read-only mount below makes impossible.
      # Sending logs to stdout instead is also what puts them in Loki, since
      # Alloy already tails this VM's socket.
      LOG_TARGETS: stdout
    volumes:
      # The repo IS the source of truth for this stack — same arrangement as
      # infra/traefik/dynamic/ and infra/forgejo/config.yml. Read-only so the
      # container can never write into the checkout.
      #
      # CAUTION: :ro means every file Homepage expects must already exist.
      # Upstream copies a skeleton file in when one is missing and calls
      # process.exit(1) when that copy fails, so a missing config file here is a
      # boot loop rather than a warning. All NINE skeleton files ship in
      # ./config for exactly that reason; four of them are stubs.
      - ./config:/app/config:ro
      # Container discovery and state for this VM's stacks. The SIXTH socket
      # mount in the lab, after Dockge, the Forgejo runner, Traefik, Alloy and
      # Uptime Kuma, and it carries the same caveat: `:ro` makes the MOUNT
      # read-only, NOT the API behind it. This is root-equivalent control of the
      # VM's Docker. Acceptable only because this is a single-tenant box.
      - /var/run/docker.sock:/var/run/docker.sock:ro
    labels:
      traefik.enable: "true"
      traefik.http.routers.homepage.rule: Host(`home.thefipster.de`)
      traefik.http.routers.homepage.entrypoints: websecure
      traefik.http.services.homepage.loadbalancer.server.port: "3000"
      # Gate the UI behind Authentik (per-app forward auth). Homepage has NO
      # login of its own, which is exactly the case this pattern exists for —
      # same as Dockge and the Traefik dashboard. The middleware and the
      # /outpost.goauthentik.io/ router for this host live on the Authentik
      # `server` container (infra/authentik). Authentik must be up first, else
      # Traefik reports an undefined middleware and this router won't load.
      # Break-glass: comment this line and `docker compose up -d` to bypass.
      traefik.http.routers.homepage.middlewares: authentik@docker
    networks:
      # `proxy` only. The Kuma widget reaches http://uptime-kuma:3001 across
      # this network — container to container, no TLS hop, no trip through
      # Traefik. Everything else on the page is a link.
      - proxy

networks:
  proxy:
    external: true
```

- [ ] **Step 8: Write `scripts/init-homepage.sh`**

```bash
#!/usr/bin/env bash
#
# init-homepage.sh — project-specific setup for the Homepage stack.
#
# Assumes Docker is installed (run scripts/init-docker.sh first). Steps:
#   1. Ensure the shared `proxy` network exists.
#   2. Symlink the stack into /opt/stacks so Dockge can manage it.
#
# That is the whole script, and it is the thinnest one here. There is NO .env
# and nothing to generate — every widget is token-free — and there is NO
# /opt/homepage, because this stack has no persistent state at all: its entire
# configuration is the git-tracked YAML in infra/homepage/config, bind-mounted
# read-only. It is the first stack in the repo with no data directory, which is
# also why it has no backup.sh.
#
# Re-runnable: every step is idempotent. Run from anywhere.
# Usage (from the repo root):
#   scripts/init-homepage.sh

set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
REPO_ROOT="$(cd "${SCRIPT_DIR}/.." && pwd)"
STACK_DIR="${REPO_ROOT}/infra/homepage"

run_root() {
  if [ "$(id -u)" -eq 0 ]; then
    "$@"
  else
    sudo "$@"
  fi
}

if ! command -v docker >/dev/null 2>&1; then
  echo "docker not found — run scripts/init-docker.sh first." >&2
  exit 1
fi

echo "==> Ensuring the shared 'proxy' network exists"
if docker network inspect proxy >/dev/null 2>&1; then
  echo "    proxy network already exists"
else
  docker network create proxy
  echo "    created proxy network"
fi

echo "==> Symlinking the stack into /opt/stacks/homepage"
run_root mkdir -p /opt/stacks
if [ -L /opt/stacks/homepage ]; then
  echo "    /opt/stacks/homepage already a symlink -> $(readlink -f /opt/stacks/homepage)"
elif [ -e /opt/stacks/homepage ]; then
  echo "    /opt/stacks/homepage exists and is NOT a symlink — leaving it alone." >&2
  exit 1
else
  run_root ln -s "${STACK_DIR}" /opt/stacks/homepage
  echo "    linked /opt/stacks/homepage -> ${STACK_DIR}"
fi

cat <<EOF

Done. Next:
  cd ${STACK_DIR} && docker compose up -d

Then https://home.thefipster.de — Authentik will ask you to log in first.
Guide: docs/homepage-setup.md
EOF
```

**Runs on:** infra VM

**Prerequisite:** [uptime-kuma-setup.md](uptime-kuma-setup.md) complete —
Homepage links every stack above it and reads Kuma's status page, so it is built
after all of them.

[Homepage](https://github.com/gethomepage/homepage) is a static start page at
**`https://home.thefipster.de`**: every service in the lab in one place, with
live container state for this VM's stacks read from the Docker API, and plain

## Troubleshooting

**The container exits immediately with `Failed to initialize required config`.**
A file is missing from `infra/homepage/config`. Under the read-only mount
Homepage cannot copy its skeleton in, and it calls `process.exit(1)` rather than
carrying on. All nine must be present:

```bash
ls -1 infra/homepage/config
```

Expected: `bookmarks.yaml custom.css custom.js docker.yaml kubernetes.yaml
proxmox.yaml services.yaml settings.yaml widgets.yaml`.

**Every page load returns 400.** `HOMEPAGE_ALLOWED_HOSTS` does not match the
`Host` header Traefik forwards. It is set in `compose.yaml` and must be exactly
`home.thefipster.de`, no scheme and no port.

**Traefik logs `middleware "authentik@docker" does not exist`.** Authentik is
down or was recreated after Homepage. Bring Authentik up; if you need the page
during an Authentik outage, comment the `middlewares` label and
`docker compose up -d`. Uncomment it afterwards.

**The page loads but every tile is grey.** The socket mount is missing or the
`server: infra` key in `services.yaml` does not match the key in `docker.yaml`.

```bash
docker compose exec homepage ls -l /var/run/docker.sock
```

**A single tile is grey.** That container's name changed. Compare
`services.yaml` against `docker ps --format '{{.Names}}'`, and fix
[uptime-kuma-monitors.md](uptime-kuma-monitors.md) at the same time — the two
files hold the same names on purpose.

**The Uptime Kuma widget is blank.** The `homelab` status page is gone, renamed,
or no longer public. Recreate it in Kuma with that exact slug; the registry row
is [The `homelab` status page](uptime-kuma-monitors.md#the-homelab-status-page).

## Design notes

**Why the infra VM.** The apps VM is the other plausible home, and it would have
been cheaper by one DNS record. It loses on the socket: Homepage's container
integration reads a Docker API, and the daemon with the lab's stacks on it is
this one. Coolify owns the apps VM's daemon, its container names are generated,
and it cannot see this machine at all. The second argument is the gate — Homepage
ships no authentication, and the forward-auth middleware exists only on this VM's
Traefik. The full comparison is in
[the design spec](superpowers/specs/2026-08-08-homepage-design.md).

**Why the config mount is read-only, and what it costs.** `:ro` is what keeps
the checkout the source of truth — the same arrangement as Traefik's `dynamic/`
directory and Forgejo's `config.yml`. It costs two things. Homepage's default
logfile lives inside the config directory, so `LOG_TARGETS: stdout` is required
rather than tidy — and that is what puts the logs in Loki, since Alloy tails
this VM's socket. And every file Homepage looks for must already exist, because
its fallback is to copy a skeleton in and exit when it cannot. Four of the nine
files are stubs for exactly that reason.

**Why there are no token-backed widgets.** Forgejo, Grafana, Authentik, Traefik,
Prometheus, Coolify and Home Assistant all have Homepage widgets, and every one
of them wants an API token. Together they would give this stack an `.env`, an
`.env.example` and a backup obligation it does not currently have. The
token-free page — container state plus one status page — is what a start page
needs. Adding a widget later is an additive change, and the first one added is
what introduces the `.env`.

**Why the observability containers are not on the page.** Prometheus, Loki,
Tempo and Alloy have no routed UI, so a tile for them would be a status dot with
nowhere to click. Kuma already watches all four by container and Grafana is where
you go to read them. This is a deliberate omission, not an oversight.

**Why it has no backup.** Every byte this stack owns is in git: the compose, the
nine config files, and no `.env`. A restic snapshot of it would be a snapshot of
a checkout. It is the only stack in the lab where that is true —
[roadmap/backup.md](roadmap/backup.md) records the absence beside the tiers.

**Why it is gated when Kuma is not.** Both are UIs with no OIDC, so the
convention points both at forward-auth, and Kuma is a stated exception because
gating the outage dashboard makes an Authentik outage the one failure you cannot
see. Homepage has no such claim: it is a page of links whose targets can be typed
by hand. Gating it is the default, and the exception list stays at three.

**The page can rot silently.** Container names in `services.yaml` are derived
from compose project and service names, so renaming a stack leaves a permanently
grey tile and nothing goes red. The same names live in
[uptime-kuma-monitors.md](uptime-kuma-monitors.md); change them together.
